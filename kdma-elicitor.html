Countervailing Co-Deployment · Module C

KDMA Elicitor

The calibrator's most fragile input is a three-option selector: does the decision trade one contested value against another? This module replaces the guess with a walk. It helps you name the values in tension, locate where the balance is struck, and test whether the fight is really about values at all — producing the KDMA level, the tension line, and a written justification the Due Process Calibrator reads directly.

This instrument characterizes the decision, never the decision-maker. KDMA here means key decision-making attributes, after DARPA's In the Moment research line — properties of decisions in domains with no single right answer. It is not a personality assessment, profiles no individual, and stores nothing: export what you need, the page forgets the rest. A design instrument · no storage · MIT License

Step 1

Name the decision

One system, one decision. Not "the SNAP system" — the specific adverse call: flags a claim as fraudulent, denies an application, sets an appointment, computes an amount.

Try three worked examples first, or write your own.

Step 2

Name the values in tension

Every automated benefits decision serves something the state wants and touches something the person needs. Pick one from each side, or write your own — the pair becomes the tension line.

Both happen. If several tensions run through one decision, elicit the dominant one here and run the walk again for the second — the calibrator takes one tension line, and the justification can name the rest. If no pair fits at all, that is itself a finding: write the decision's real stakes in your own words in the boxes, the chips are prompts, not categories you owe anything to.

Step 3

Three probes

The level comes from the first and third probes. The second doesn't change the level — it changes who should answer for the choice, and it feeds the calibrator's opacity inputs.

Could two reasonable officials, both following the rules, decide this same case differently because they weight these values differently?

How the level is derived

Probe 1 answered "no" → Level 0, largely ministerial rules, whatever the other probes say: without a genuine trade-off there is no KDMA, and disputes belong to the risk-of-error input instead. Probe 1 "yes" with a marginal choice → Level 1, contested at the margins. Probe 1 "yes" with a central choice → Level 2, a core value trade-off. Probe 2 never changes the level — a trade-off struck visibly in statute still intensifies the duty once it acts through automation — but it changes the justification and, when the balance is struck inside the software, it should also raise the calibrator's Opacity and Proprietary-secrecy inputs.

    About

    How this tool works

    1. Why contested values intensify the duty

    The Countervailing Co-Deployment framework measures what the state owes when it automates decisions over people. Most of that measure is about error and asymmetry. KDMA adds a third thing: some automated decisions do not merely apply a rule — they act out a choice between values that reasonable people weigh differently, program integrity against access to food, speed against individualized assessment. When that happens, the risk in Mathews terms stops being only factual error, which better data could fix, and becomes value misalignment, which only procedure can surface: the person must be able to see the choice, argue against its application to them, and reach a human who owns it. That is why a KDMA above zero triggers the calibrator's four mandatory safeguards — individualized reasons, a route for evidence, human review, and an appeal — whatever the rest of the score says. The concept is adopted from DARPA's In the Moment research line, which characterizes decisions in domains without a single right answer through key decision-making attributes so that algorithms can be aligned to trusted human decision-makers; a benefits system that embeds such choices without surfacing them owes the affected person more, not less.

    2. What this tool is not

    It is not a personality or psychometric assessment. "KDMA" is sometimes expanded elsewhere as key decision-maker attributes and turned into profiles of individuals; this module does the opposite on purpose. It characterizes one decision made by one system, and no answer here says anything about any person's mind.

    3. The level logic, in one table

    • Level 0 · No, largely ministerial rules. No genuine trade-off: the rule dictates the outcome. Real disputes are factual — feed them to the calibrator's risk-of-error input, not here.
    • Level 1 · Partly, contested at the margins. A genuine trade-off that surfaces at the edges: tie-breaks, prioritization, timing.
    • Level 2 · Yes, a core value trade-off. The adverse decision is the value choice acting on the person.
    • Where the balance is struck — statute, agency policy, or software design — never changes the level, but it changes who must answer for the choice, and a balance struck inside software should raise the calibrator's Opacity and Proprietary-secrecy inputs.
